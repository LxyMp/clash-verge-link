# Firefox 扩展逻辑修复与日志功能移除设计

## 目标

修复代码审查中发现的代理状态、设置保存和国际化问题，并彻底移除连接日志功能及其权限、设置和数据结构。完成自动测试、构建、Firefox 扩展检查和 Zen 浏览器本机验证后，再统一提交 Git。

## 范围

### 代理控制

- Clash REST API 离线时，如果扩展代理当前已开启，用户仍可关闭代理。
- Clash REST API 离线时，如果扩展代理当前未开启，不允许开启代理，避免把 Firefox 指向不可用端口。
- 查询代理状态时同时检查代理配置和 `levelOfControl`，只有配置匹配且由本扩展控制时才显示为开启。
- 后台启动恢复代理或端口变化后重设代理失败时，清理代理配置并将持久化的 `proxyEnabled` 回滚为 `false`。

### 设置保存

- API 地址、端口和其他字段继续进行格式、范围校验。
- API Secret 允许为空，与默认设置及 Clash API 客户端现有行为保持一致。
- 纯本地设置直接保存；仅在 API 地址或 Secret 变化时执行连接测试。
- Clash 连接测试失败不阻止保存，保存成功后向用户显示连接失败警告。
- 候选 API 配置的连接测试不得污染页面当前使用的 API 客户端配置。

### 删除日志功能

- 删除设置页日志导航和日志表格组件。
- 删除后台连接缓存、轮询、闹钟和 `GET_CONNECTIONS` 消息处理。
- 删除日志相关设置字段、类型、文案和界面控件。
- 从 manifest 中删除仅供日志轮询使用的 `alarms` 权限。
- 设置标准化时只返回当前明确支持的字段，使旧存储中的日志字段在下次保存时自然清除。

### 国际化

- locale 文件加载失败时不更新已加载语言标记，使后续调用可以重试。
- 加载失败时清空自定义消息并回退到 `browser.i18n`，避免错误地继续显示上一种语言。

## 错误处理

- 代理操作失败通过后台消息返回明确错误；持久化状态与实际状态保持一致。
- 设置连接测试区分“保存失败”和“连接测试失败”：存储失败显示错误，测试失败显示警告但保留已保存配置。
- 删除日志功能后，不再保留连接请求失败或陈旧缓存状态。

## 测试与验收

- 扩充纯函数测试，覆盖 Firefox 代理控制权判断、配置匹配和空 Secret 校验。
- 对后台代理恢复和回滚逻辑尽可能抽出可测试函数；无法直接单测的浏览器 API 路径通过构建和本机交互验证。
- 运行 `yarn test`、`yarn build` 和 `yarn lint:addon`。
- 在 Zen 浏览器临时安装构建产物，验证：在线开启/关闭、Clash 离线时关闭、设置离线保存、空 Secret 保存、主题和语言切换。
- 检查最终 diff，确认无日志相关实现、权限或文案残留，再提交 Git。
